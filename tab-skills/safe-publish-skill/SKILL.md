# בקרה לפני פרסום · סקיל לטאב של מורה

> **לטאב שקורא את זה:** מהיום, לפני **כל** פרסום של תוצר ציבורי (אתר, דף, משחק, מעבדה, קובץ להורדה, עדכון של אתר קיים), אתה מריץ את הבקרה שבסקיל הזה. מה שנכשל עוצר את הפרסום. רק המורה יכולה להחליט במפורש לעקוף, ואז אתה רושם את זה. אין גורם מרכזי שבודק: אתה הבודק.

## 1. מה הסקיל עושה

שמונה בדיקות, דוח קצר אחד, ושער שלא נפתח עד שהכל עובר:

| # | נושא | מה בודקים בקצרה | אוטומטי |
|---|---|---|---|
| 1 | אבטחת מידע | מפתחות, סיסמאות, קודי העלאה, קישורים עם קוד, מיילים וטלפונים, קבצי ‎.env‎, נתיבי ניהול פתוחים | `security.mjs` |
| 2 | פרטיות תלמידים | שמות מלאים, ת״ז, ציונים, תמונות עם מיקום, סקריפטים של מעקב, טפסים שאוספים מידע | `privacy.mjs` |
| 3 | זכויות יוצרים | לכל תמונה, סרטון, גופן וטקסט שאול יש מקור ורישיון רשומים | `sources.mjs` |
| 4 | קרדיטים | בלוק קרדיטים גלוי עם כל מי שצריך, בשם שהוא ביקש, ובקשות לגבי AI מכובדות | `sources.mjs` |
| 5 | נגישות | שפה וכיוון, טקסט חלופי, כותרות, ניגודיות, תוויות, כתוביות, מקלדת, זום | `a11y.mjs` (+`axe.mjs`) |
| 6 | דיוק מדעי | כל טענה נבדקה מול מקור אמין, מונחים לפי הכללים של המורה | `facts.mjs` + בדיקה שלך |
| 7 | מפתחות תשובות | אין מחוון, פתרונות או תשובות למבחן בשום קובץ שתלמיד יכול להגיע אליו | `keysafe.mjs` |

הכל בקובץ אחד שמריץ את כולם: `checks/gate.mjs`. בלי תלויות, Node 18 ומעלה.

## 2. התקנה (פעם אחת)

1. הורד את `safe-publish-skill.zip` מדף הסקיל ופתח אותו בתיקיית הקבצים שלך, למשל `/home/user/tab/files/safe-publish-skill/`.
2. בדוק שהבקרה רצה: `node checks/gate.mjs <תיקייה כלשהי שפרסמת>`.
3. כתוב בזיכרון שלך (קובץ כללים קבוע) את הכלל: *"לפני כל פרסום: `node /home/user/tab/files/safe-publish-skill/checks/gate.mjs <תיקיית הפרסום>`. ❌ = לא מפרסם. עקיפה רק במילים מפורשות של המורה, ונרשמת ב-`memory/publish-overrides.md`."*
4. שאל את המורה שתי שאלות, לא יותר:
   - "יש מונחים שאת מקפידה עליהם בכיתה (מילה שלא משתמשים בה ומה במקומה)?" אם כן, צור `TERMS.md` (תבנית ב-`templates/`).
   - "יש לך רשימת שמות תלמידים שאני מכין עבורה חומרים?" אם כן, שמור אותה **רק** בתיקייה פרטית (לא בתיקיית פרסום), והפנה אליה מ-`student_names_file`. הבדיקה משתמשת בה כדי לוודא ששום שם מלא לא מתפרסם.
5. ספר למורה במשפט אחד שהבקרה פעילה, ושאם היא אי פעם רוצה לפרסם למרות כישלון, מספיק לומר זאת במפורש.

## 3. השער: מה עושים לפני כל פרסום

1. **מכינים את תיקיית הפרסום** כרגיל. ליד התיקייה (תיקייה אחת מעליה, לא בתוכה) מניחים:
   - `publish-gate.json` — הגדרות האתר (תבנית ב-`templates/`).
   - `FACTCHECK.md` — טבלת הטענות שבדקת (סעיף 6.6).
   - `TERMS.md` — אם למורה יש כללי מונחים.
   - בתוך תיקיית הפרסום: `sources.json` — מקור ורישיון לכל קובץ מדיה (סעיף 6.3).
2. **מריצים:** `node checks/gate.mjs <publish-folder> --json gate-report.json`
3. **אחרי פרסום של אתר עם שרת** (worker, API, אזור מורה) מריצים שוב עם `--live https://<האתר>` — זה מוודא ש-‎/.env‎, ‎/.git‎ ונתיבי ניהול לא עונים 200, ושכל נתיב ב-`protected_paths` (למשל מחוונים) חסום בלי כניסת מורה. הוא גם פונה לנתיבי הנתונים הנפוצים (‎/api/report‎, ‎/api/results‎, ‎/api/analytics‎, ‎/api/students‎ ומה שב-`auth.teacher_paths`) ומוודא שהם לא מחזירים נתונים בלי אסימון. עם `--probe-login` (ו-`auth.login_path`) הוא שולח 12 ניסיונות שגויים ובודק שהכניסה ננעלת. אם יש Playwright בקופסה: `node checks/axe.mjs https://<האתר>` לבדיקת נגישות עמוקה ב-390 וב-1366 פיקסלים.
4. **קוראים את הדוח:**
   - ❌ באחד הנושאים → **לא מפרסמים.** מתקנים בעצמך את מה שאפשר (רוב התיקונים לוקחים שניות: מוחקים מפתח, מוסיפים alt, מוסיפים שורה ל-sources.json), ומריצים שוב.
   - ⚠️ → מותר לפרסם, אבל כל ⚠️ אתה בודק בעצמך, ומה שנשאר נאמר למורה במשפט אחד בהודעת הפרסום.
   - ✅ בכל השורות → מפרסמים.
5. **מה שלא נבדק אוטומטית בודקים בעיניים**, על צילום מסך של הדף בטלפון (390 פיקסלים): מידע שמועבר רק בצבע (✔ ירוק / ✘ אדום בלי מילה או סמל), סדר מקלדת הגיוני (Tab עובר על הכל, אין מלכודת), תמונה שמציגה תלמיד מזוהה, וטקסט שהועתק מאתר אחר.

**כלל ברזל:** אף פעם לא משנים או מכבים בדיקה כדי שתעבור. מתקנים את התוצר, או שהמורה עוקפת במפורש.

## 5. עקיפה (המורה מחליטה לפרסם בכל זאת)

הבקרה מחייבת, אבל ההחלטה הסופית של המורה. כשהמורה רוצה לפרסם למרות ❌:

1. **מראים בדיוק מה נכשל**, בשפה פשוטה ועם הסיכון במשפט: *"נכשל: זכויות יוצרים — 2 תמונות בלי מקור. אם הן של מישהו אחר, הוא יכול לדרוש להוריד."*
2. **מבקשים אישור ברור**, לא "אוקי" עמום: *"לפרסם בכל זאת, למרות זכויות יוצרים? כתבי 'כן, לפרסם למרות'."* תשובה עמומה ("נו", "בסדר") = שואלים שוב פעם אחת.
3. **רושמים** לפני הפרסום:
   `node checks/gate.mjs override --log memory/publish-overrides.md --site "<שם>" --failed "<הנושאים>" --words "<המילים המדויקות של המורה>"`
   השורה נשמרת עם תאריך, פריט, מה נכשל ומה המורה כתבה, מילה במילה.
4. **מפרסמים**, ומזכירים במשפט מה נשאר פתוח.

כללים לעקיפה:
- עקיפה תקפה **לפרסום הזה בלבד**. בפרסום הבא בודקים מחדש.
- מפתח או סיסמה אמיתיים שפורסמו (גם בעקיפה): מחליפים אותם מיד אחרי (מפתח חדש, קוד חדש), כי מה שעלה לרשת כבר לא סוד.
- "תפסיק לבדוק" כבקשה כללית: מסבירים במשפט שהבדיקה לוקחת שניות ומגינה עליה, ושואלים אם היא רוצה לכבות נושא מסוים. אם כן, רושמים בזיכרון מה כובה ומתי.

## 6. הנושאים: כללים, מה בודקים, איך מתקנים

### 6.1 אבטחת מידע

**כללים**
- שום סוד בקבצים ציבוריים: מפתחות API, סיסמאות, טוקנים, קודי העלאה, מפתחות ניהול, קישורי העלאה עם קוד.
- סודות נשמרים רק במקום נעול בקופסה (למשל `/home/user/tab/state/secrets/`, הרשאות 600), לעולם לא בתיקיית פרסום, לא בזיפ ולא בצילום מסך.
- כל נתיב ניהול/מורה בשרת דורש מפתח או כניסה, ובלעדיהם עונה 401/403.
- פרטי קשר אישיים (מייל, טלפון) רק אם המורה ביקשה שיופיעו. מייל למשוב שהיא בחרה → `allowed_emails`.

**מה `security.mjs` בודק:** תבניות של מפתחות מוכרים (sk-, AKIA, ghp_, xox, sk_live, JWT, Bearer, מפתח פרטי), השמות כמו `password = "..."`, קישורים עם `?code=` / `?token=`, מיילים, טלפונים ישראליים, קבצי ‎.env‎, ‎.pem‎, ‎.git‎, מסדי נתונים, גיבויים ו-source maps, וקוד שרת עם ‎/admin‎ בלי 401/403. גם קבצים **בתוך zip** נבדקים.

**תיקון:** מוחקים את הערך מהקובץ, טוענים אותו מהשרת/סביבה, מחליפים מפתח שדלף, מוציאים קבצים מסוכנים מתיקיית הפרסום. מפתח Firebase לאתר (‏AIza…) הוא ציבורי מטבעו: ⚠️ בלבד, בתנאי שהוא מוגבל לדומיין.

### 6.2 פרטיות תלמידים

**הקשר:** חוק הגנת הפרטיות (התשמ״א-1981) ותיקון 13 שנכנס לתוקף ב-14.8.2025, ו"מדריך פרטיות תלמידים במוסדות חינוך בעידן הדיגיטלי" של הרשות להגנת הפרטיות. הנוסח המחייב הוא החוק והנחיות משרד החינוך העדכניות; כשיש ספק, בודקים שם, לא מנחשים.

**כללים**
- מינימום מידע. תלמידים מזוהים בשם פרטי, אימוג׳י או כינוי, לא בשם מלא.
- אף פעם לא: ת״ז, ציונים, הערות התנהגות, אבחונים, כתובות, טלפונים של תלמידים או הורים בדף ציבורי.
- צילום או סרטון של תלמידים מתפרסם רק בהסכמת הורים, ועדיף בלי פנים ובלי שם. מוחקים מטא-דאטה (מיקום GPS) מכל תמונה.
- אין סקריפטים של מעקב או פרסום (Google Analytics, Pixel, Hotjar, Clarity…). תוכן מוטמע מינימלי: YouTube דרך youtube-nocookie.com, גופנים מאוחסנים באתר עצמו.
- התקדמות תלמידים נשמרת במכשיר שלהם או מאחורי כניסה של הכיתה, לא בקובץ ציבורי.

**מה `privacy.mjs` בודק:** מספרים שהם ת״ז תקינה (ספרת ביקורת), שמות מלאים מהרשימה הפרטית של המורה, טבלאות עם עמודת ציון, קובצי CSV עם ציונים, סקריפטים של מעקב, הטמעות ופונטים מצד שלישי, טפסים ששולחים מידע החוצה ושדות מייל/טלפון/שם מלא, עוגיות, ותמונות JPEG עם EXIF/GPS.

**תיקון:** מחליפים שם מלא בשם פרטי, מוחקים עמודות מזהות, מסירים סקריפטי מעקב, מעבירים פונטים לאחסון מקומי, שומרים תמונות מחדש בלי מטא-דאטה (למשל `ffmpeg -i in.jpg -map_metadata -1 out.jpg`).

### 6.3 זכויות יוצרים

**הקשר:** חוק זכות יוצרים, התשס״ח-2007. סעיף 19 מתיר "שימוש הוגן" למטרות כמו "הוראה ובחינה על ידי מוסד חינוך", לפי ארבעה שיקולים: מטרת השימוש ואופיו, אופי היצירה, היקף השימוש ביחס ליצירה כולה, והשפעתו על ערך היצירה ושוקה. שימוש בכיתה אינו זהה לפרסום פתוח לכל העולם: באתר ציבורי מעדיפים קישור למקור על פני העתקה.

**כללים (לפי סדר עדיפות)**
1. **שלנו:** תוכן שהמורה או הטאב יצרו (כולל תמונות שנוצרו בבינה מלאכותית).
2. **רישיון פתוח:** CC0, נחלת הכלל, CC BY / BY-SA (עם קרדיט), גופנים ב-OFL.
3. **רשות:** אישור בכתב מהיוצר (שומרים מי ומתי).
4. **שימוש הוגן:** קטע קצר, לצורך לימודי, עם נימוק כתוב. מסומן ⚠️ כדי שהמורה תדע.
- לא מעתיקים אתרים, דפי עבודה, איורים מספרי לימוד או סרטונים של אחרים. קישור — כן; העתקה — לא.

**`sources.json`** (בתיקיית הפרסום):

```json
{
  "assets": [
    { "file": "img/cell.webp", "source": "generated", "license": "generated", "note": "נוצר עבור השיעור" },
    { "file": "img/leaf-*.jpg", "source": "https://commons.wikimedia.org/wiki/File:...", "license": "CC BY-SA 4.0", "creator": "שם היוצר" },
    { "file": "fonts/Rubik.woff2", "source": "https://fonts.google.com/specimen/Rubik", "license": "OFL", "creator": "Hubert & Fischer" },
    { "what": "ציטוט מתוך מאמר", "source": "https://...", "license": "fair-use", "note": "שתי שורות, לצורך דיון בכיתה" }
  ],
  "people": [
    { "name": "שם", "credit_as": "השם כפי שביקשה", "for": "הרעיון למשחק", "ai_credit": "mention" }
  ]
}
```

`file` מקבל `*` בשם קובץ. ערכי רישיון מוכרים: `own`, `generated`, `CC0`, `public-domain`, `CC BY…`, `OFL`, `MIT`, `permission` (חייב `note`), `fair-use` (חייב `note`).

**מה `sources.mjs` בודק:** כל קובץ מדיה/גופן רשום עם מקור ורישיון מותר, תמונות/סרטונים שנטענים ישירות מאתר אחר, וסימנים לדף שהועתק (saved from, HTTrack, ארכיון).

**תיקון:** רושמים מקור; מה שאין לו מקור מותר מחליפים בתמונה שנוצרת או בתמונה ברישיון פתוח; תוכן מועתק כותבים מחדש במילים שלנו או מחליפים בקישור.

### 6.4 קרדיטים

**הקשר:** סעיף 46 בחוק זכות יוצרים: ליוצר יש זכות מוסרית "כי שמו ייקרא על יצירתו בהיקף ובמידה הראויים בנסיבות העניין".

**כללים**
- בכל תוצר שמשתמש בעבודה או ברעיון של מישהו יש בלוק קרדיטים גלוי (`<section id="credits">` או כותרת "קרדיטים"/"תודות").
- השם בדיוק כפי שהאדם ביקש (`credit_as`). לא מוסיפים תואר, שם משפחה או בית ספר בלי שביקש.
- בקשות לגבי AI מכובדות: `"ai_credit": "mention"` = לציין שנעשה בסיוע בינה מלאכותית; `"ai_credit": "omit_name"` = האדם לא רוצה ששמו יופיע (למשל לצד AI), ואז שמו לא מופיע בשום קובץ.
- קרדיט למורה עצמה ולבית הספר רק אם היא רוצה.

**מה נבדק:** בלוק קרדיטים קיים כשצריך, כל `creator` של רישיון שמחייב קרדיט וכל `people` מופיעים בו בשם הנכון, ובקשות ה-AI מתקיימות.

### 6.5 נגישות

**הקשר:** חוק שוויון זכויות לאנשים עם מוגבלות ותקנה 35 לתקנות הנגישות לשירות (2013) מפנות לתקן הישראלי ת״י 5568, שמבוסס על הנחיות WCAG ברמה AA. אנחנו מכוונים ל-**WCAG 2.1 AA**, שכולל אותו ויותר. מומלץ להוסיף הצהרת נגישות קצרה עם דרך לפנות (תבנית ב-`templates/`).

**כללים**

- לכל תמונה `alt` שמתאר מה רואים ולמה זה חשוב (תמונה דקורטיבית: `alt=""`). אייקון SVG: `aria-hidden="true"`.

- ניגודיות לפחות 4.5:1 לטקסט רגיל, 3:1 לטקסט גדול (24px, או 18.66px מודגש) ולרכיבי ממשק.
- גודל טקסט בסיסי 16px ומעלה, ושום טקסט מתחת ל-12px.
- כל פעולה זמינה במקלדת (`<button>`, `<a>`, לא `div` עם onclick), עם מסגרת פוקוס גלויה.

- לינקים עם טקסט שמסביר לאן ("לדף העבודה", לא "לחצו כאן").

### 6.8 הגנה בסיסמה והזדהות

**מתי זה חל:** בכל אתר שיש בו משהו שרק המורה אמורה לראות או לעשות: לוח מורה, דוחות ונתוני תלמידים, מחוונים, ניהול, העלאת קבצים, עריכה.

**כללים לכל אזור מורה**
- **ננעל בשרת, לא בדפדפן.** דף "סודי" שאין לו קישור, או סיסמה שנבדקת ב-JavaScript, פתוחים לכל מי שלוחץ "הצג מקור". השרת (worker / API) בודק את הכניסה בכל בקשה, ועונה 401/403 בלי כניסה.
- **סיסמה או קוד מתאימים:**
   - לא בקוד הדפדפן ולא ב-HTML, לא בקובץ JSON ציבורי ולא בזיפ.
   - **אף פעם לא בקישור** (`?password=`, `?key=`): קישורים נשמרים בהיסטוריה, ביומני שרת ובהודעות שמעבירים הלאה. שולחים בכותרת או בגוף בקשת POST.
   - ארוך מספיק: קוד מורה של 12 תווים לפחות, או 4 מילים אקראיות. לא שם בית הספר, לא שנה, לא 1234.
   - בשרת נשמר רק **גיבוב או HMAC** של הקוד (בסוד של השרת, `crypto.subtle`), וההשוואה בזמן קבוע. הקוד עצמו לא נשמר בשום מקום.
   - **נעילה אחרי ניסיונות שגויים:** אחרי 5 ניסיונות, נעילה ל-15 דקות (תשובה 429). זה חשוב במיוחד לכניסת תלמידים קצרה (3 אימוג׳ים מתוך 12 הם רק 1,728 אפשרויות).
   - **דלף? מחליפים.** קוד שהופיע בהודעה, בצילום מסך או בקובץ שפורסם כבר לא סוד: מחליפים מיד, גם אם זה היה בעקיפה.

**כשהמורה עוקבת אחרי נתוני תלמידים ואנליטיקות** (דוחות התקדמות, ציונים, זמני משחק, תשובות)
- **ממליצים בחום על כניסת מורה עם גוגל** (Firebase Authentication או Google Identity Services), כמו במעבדות של madalabs. בלי זה: ⚠️. נתוני תלמידים שנשמרים או חוזרים מהשרת **בלי שום כניסה**: ❌.
- **רשימת מורים מורשים:** השרת מכניס לאזור המורה רק כתובות שמופיעות ברשימה (`TEACHER_EMAILS` בסוד של השרת), ולא "כל מי שיש לו חשבון גוגל". הרשאות ניהול (כל הכיתות, אישור תכנים) רק לכתובת מהרשימה.
- **לא סומכים על הדפדפן:** הדפדפן שולח את אסימון ה-ID של גוגל, והשרת מאמת אותו בעצמו בכל בקשה: חתימה מול המפתחות של גוגל, `aud` = מזהה הפרויקט, `iss`, תוקף (`exp`), `email_verified`. "הדפדפן אמר שזו המורה" זה לא אימות.
- **דומיינים מורשים:** ב-Firebase מוסיפים לרשימת Authorized domains רק את כתובת האתר, ומגבילים את מפתח ה-Web API לאותו דומיין.
- **ניהול רק דרך גוגל:** אם יש גם כניסה במייל וקוד (למשל למורה אורחת), היא לעולם לא נותנת הרשאות ניהול.
- **תלמידים נשארים עם כניסה קלה:** שם פרטי + קוד כיתה + אימוג׳י סודי או PIN קצר. לא צריך חשבון גוגל לילדים, לא מייל ולא טלפון (וזה גם מה שפרטיות התלמידים בסעיף 6.2 מבקשת). הכניסה הזאת נעולה אחרי ניסיונות שגויים, והתלמיד רואה רק את הנתונים של עצמו.

אימות אסימון גוגל בשרת (Cloudflare Worker, בלי תלויות):

```js
// השרת מאמת בכל בקשה לנתוני תלמידים: חתימה, פרויקט, תוקף, ורשימת המורים
const JWKS = 'https://www.googleapis.com/service_accounts/v1/jwk/securetoken@system.gserviceaccount.com';
const bytes = s => Uint8Array.from(atob(s.replace(/-/g, '+').replace(/_/g, '/')), c => c.charCodeAt(0));
const json = s => JSON.parse(new TextDecoder().decode(bytes(s)));
export async function teacherFrom(req, env) {
  const [h, p, sig] = (req.headers.get('authorization') || '').replace(/^Bearer /, '').split('.');
  if (!sig) return null;
  const head = json(h), pl = json(p), now = Date.now() / 1000;
  const jwk = (await (await fetch(JWKS)).json()).keys.find(k => k.kid === head.kid);
  if (!jwk || head.alg !== 'RS256') return null;
  const key = await crypto.subtle.importKey('jwk', jwk, { name: 'RSASSA-PKCS1-v1_5', hash: 'SHA-256' }, false, ['verify']);
  const ok = await crypto.subtle.verify('RSASSA-PKCS1-v1_5', key, bytes(sig), new TextEncoder().encode(h + '.' + p));
  if (!ok || pl.aud !== env.FIREBASE_PROJECT || pl.iss !== 'https://securetoken.google.com/' + env.FIREBASE_PROJECT) return null;
  if (pl.exp < now || !pl.email_verified) return null;
  const allowed = env.TEACHER_EMAILS.split(',').map(e => e.trim().toLowerCase());
  return allowed.includes(pl.email.toLowerCase()) ? { email: pl.email } : null; // אחרת: 403
}
```

קוד מורה בלי גוגל (אתר קטן, בלי נתוני תלמידים): השרת שומר רק HMAC של הקוד, ונועל אחרי 5 ניסיונות:

```js
const enc = new TextEncoder();
async function hmacHex(secret, text) {
  const k = await crypto.subtle.importKey('raw', enc.encode(secret), { name: 'HMAC', hash: 'SHA-256' }, false, ['sign']);
  return [...new Uint8Array(await crypto.subtle.sign('HMAC', k, enc.encode(text)))].map(b => b.toString(16).padStart(2, '0')).join('');
}
function same(a, b) { let d = a.length ^ b.length; for (let i = 0; i < a.length; i++) d |= a.charCodeAt(i) ^ b.charCodeAt(i % b.length); return d === 0; }
export async function checkCode(req, env) {
  const ip = req.headers.get('cf-connecting-ip') || 'x', fails = +(await env.KV.get('fail:' + ip) || 0);
  if (fails >= 5) return new Response('נסו שוב בעוד רבע שעה', { status: 429 });
  const { code } = await req.json();                      // בגוף הבקשה, לא בקישור
  if (same(await hmacHex(env.PEPPER, code || ''), env.CODE_HMAC)) return null; // עבר
  await env.KV.put('fail:' + ip, String(fails + 1), { expirationTtl: 900 });
  return new Response('קוד שגוי', { status: 401 });
}
```

**מה `auth.mjs` בודק:**
- סיסמה, PIN או קוד מורה שכתובים בקוד הדפדפן (השוואה למחרוזת, `prompt`, ‏`atob`): ❌.
- סיסמה או מפתח בקישור (`?password=`, ‏`?admin=`, מפתח ארוך ב-`?key=`): ❌. קוד שקורא סוד מהכתובת: ⚠️.
- שרת עם נתיבי מורה/ניהול או נתוני תלמידים שאף פעם לא עונה 401/403: ❌.
- כניסה בסיסמה שמשווה טקסט גלוי, או בלי נעילה אחרי ניסיונות: ⚠️.
- אתר שאוסף פעילות תלמידים בלי כניסת גוגל למורה: ⚠️. גוגל בדפדפן בלי אימות האסימון בשרת: ❌. בלי רשימת מורים מורשים: ⚠️. כניסה נוספת במייל וקוד: ⚠️ עד שמוודאים שאין לה הרשאות ניהול.
- דף מורה שהוא קובץ ציבורי רגיל, בלי שרת: ⚠️.
- עם `--live`: נתיבי דוחות ונתונים שמחזירים נתונים בלי אסימון: ❌. עם `--probe-login`: כניסה שלא ננעלת אחרי 12 ניסיונות שגויים: ⚠️.

**בודקים בעיניים:** שהתלמיד רואה רק את עצמו (מתחברים כתלמיד ומנסים לפתוח דוח של הכיתה), שיציאה מנקה את הכניסה, ושההודעה על קוד שגוי לא מגלה אם השם קיים.

ומה משותף לכולם: פוטר קטן עם קישור משוב למורה שבנתה (עם תווית נגישה שמכילה את הטקסט הגלוי), עיצוב רגוע בצבעי מנטה ותכלת, ניגודיות שעוברת AA, וגופן גדול מספיק לטלפון. כשמראים השראה, מעתיקים רעיונות, לא קוד או תוכן של אתר אחר (סעיף 6.3).
