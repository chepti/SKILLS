# פרסום והפעלה

## דרך א: עם clasp (מהירה, לבונה)
```
cd <תיקיית הפרויקט עם קבצי template>
node build.js
clasp create --type standalone --title "<שם>" --rootDir .
# clasp create דורס את appsscript.json: לשחזר אותו מהתבנית (webapp, Asia/Jerusalem)
clasp push --force
clasp deploy --description "v1"          # בפעם הראשונה: מחזיר deploymentId
# עדכונים: clasp deploy --deploymentId <ID> --description "..."
```
כתובת: `https://script.google.com/macros/s/<deploymentId>/exec`. חשבון clasp הוא החשבון שבו ייכתבו הגיליון והנתונים.

## דרך ב: בלי clasp (מורה שמעתיקה)
1. https://script.google.com ← פרויקט חדש.
2. ליצור קבצים עם אותם שמות והדבקת התוכן: `Code` ו-`Exam` (סקריפט), `Index`, `Result`, `Teacher` (HTML). את `Index.html` מכינים קודם: `node build.js` (או להחליף ידנית את `__IMG_..__` בריק).
3. בהגדרות הפרויקט: "הצג את appsscript.json" והדבקת התוכן מהתבנית.
4. פריסה ← פריסה חדשה ← אפליקציית אינטרנט: הפעלה בתור "אני", גישה "כל אחד".

## הפעלה ראשונה (חובה)
בעורך הסקריפט: לבחור `authorize` ← הפעלה ← אישור הרשאות. הפונקציה יוצרת את גיליון התוצאות ומציגה בלוג את קישורו ואת מפתח המורה (גם בלשונית "מידע"). עד שזה נעשה, הכתובת מחזירה "הגישה נדחתה" (403).

## כתובות
- תלמידות: `<כתובת>`. משוב לתלמידות: `<כתובת>?page=result`.
- מורה: `<כתובת>?page=teacher&key=<מפתח מורה>`.
- API ללא סיסמה: `<כתובת>?action=help`.

## עבודה יומיומית של המורה
1. מחלקת את הכתובת. אומרת לתלמידות איזה נוסח לבחור (לפי מקום ישיבה). כיתה נכתבת ח2. מורים מנסים עם הסימון "אני מורה" (כיתת "חולמים תקשוב").
2. בלוח המורה: סינון לכיתה, בדיקה לפי שאלה (מהיר) או לפי תלמידה, כוכבים (חצי כוכב = נקודה), משוב, אימוץ הצעת סוכן.
3. "תמונה כיתתית": לראות אילו שאלות אדומות ואיזה מסיח משך תלמידות.
4. "משובים לתלמידות": משפט כללי לכל תלמידה, פרסום לכל מי שנבדקה במלואה. התלמידות נכנסות עם הקוד האישי.
5. גיבוי: הגיליון מכיל גם טיוטות של מי שלא הגישה.

## סוכן בודק
1. `GET <כתובת>?action=toscore&key=<מפתח סוכן>&cls=ח2` ← רשימת תשובות פתוחות (שאלה, תבחינים, תשובה לדוגמה, תשובת תלמידה).
2. להציע ניקוד שלם 0..max לפי התבחינים, עם הערה (note) בגוף שני, פונה לתלמידה, במשפטים שלמים.
3. `POST` (text/plain, JSON): `{key, action:"ops", ops:[{action:"suggest", items:[{sid, field, score, note}]}]}`. הצעה מופיעה בכרטיס של המורה. המורה היא שמחליטה.
4. לא לכתוב משוב לתלמידה ולא לשנות ניקוד מורה.

System prompt להדבקה לסוכן:
> את/ה עוזר/ת בבדיקת מבדק. קרא/י את `?action=toscore`. לכל פריט יש שאלה, תבחינים (rubric), תשובה לדוגמה (model) ותשובת תלמידה. הצע/י ניקוד שלם בין 0 ל-max לפי התבחינים בלבד. בשדה note כתוב/י הערה בגוף שני, בלשון נקבה, הפונה ישירות לתלמידה ("הסברת נכון ש...", "כדאי להוסיף ש..."), במשפטים שלמים (עד שלושה), שמציינת מה היה טוב ומה חסר, כך שהמורה תוכל להעתיק אותה כמשוב. שלח/י POST ל-suggest. אל תשנה/י ניקוד מורה ואל תכתב/י את המשוב הסופי: המורה מחליטה.

## פתרון תקלות
- 403 "הגישה נדחתה": לא הורצה `authorize`, או שהארגון חוסם גישה אנונימית.
- הגשה לא נקלטת: בדקי בגיליון שלשונית "תוצאות" קיימת, ושהכתובת היא של הפריסה העדכנית.
- אחרי עדכון קוד: `clasp deploy --deploymentId` (לא פריסה חדשה, כדי לשמור כתובת).
- "לא תקין:" בעמודת כיתה: תלמידה כתבה כיתה לא בפורמט. אפשר לתקן ידנית בגיליון.
